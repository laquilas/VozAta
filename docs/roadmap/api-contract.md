# Engine API contract

Single source of truth for the engine (Python, FastAPI) and the UI (`VozAta.Client`).
Every endpoint and event is tagged with the phase that implements it; a phase implements only its
own rows. Changing a row requires updating both sides.

## Conventions

- Base URL `http://{API_HOST}:{API_PORT}` — default `http://127.0.0.1:8765`. **Never bind to
  `0.0.0.0`.**
- JSON with `snake_case` fields (the C# client maps them with `JsonNamingPolicy.SnakeCaseLower`).
- Times in segments are seconds since session start (float); timestamps are ISO 8601 with offset.
- Errors: HTTP status + `{"error": {"code": "session_not_found", "message": "<localized>"}}`.
  Codes are stable English identifiers; `message` is localized with `APP_LANGUAGE`.
- Only one recording session can be active at a time (`409 session_already_active`); meetings already
  stopped, or being recovered, do not count: they are processed by the background queue (40). A
  `POST /sessions` sent while an accepted stop is still releasing its capture waits up to 10 s for
  the slot, then starts (or answers `409 session_already_active` if the slot is still taken).
- `session.json` carries `capture_ended_at` (40): when capture stopped. A `finalizing` meeting that
  has it is re-queued when the engine starts (repair, then the processing steps); one without it was
  cut short while recording and is offered for recovery (`recovery_available`). For a meeting recovered
  after a crash during capture it is the repair time, written once the repair succeeds (a resume
  marker, not the real end of capture).
- OpenAPI is served at `/docs` (Swagger UI) and `/redoc`, both showing the VozAta favicon, and must
  match this document.

### Shapes

```jsonc
// SessionSummary
{"id": "20261015_202358", "status": "recording", "started_at": "...", "ended_at": null,
 "duration_seconds": 83.4, "language": "pt", "has_minutes": false,
 "title": "Weekly sync",  // title (35): null = untitled
 "speaker_count": 2, "has_action_items": true, "template": "daily",
 "processing": {"state": "queued", "percent": 0, "step": null, "position": 2}}
// speaker_count / has_action_items / template (36): speakers found by diarization (0 before),
//   whether the session has action items, the minutes template id in session.json (null = none)
// processing (40): null unless the meeting is in the processing queue; then
//   {state: "queued" | "running" | "paused", percent: 0-100, step: "repair" | "transcribe" |
//   "diarize" | "minutes" | "action_items" | "index" | null, position: n (only when queued,
//   1 = next)} — the same object as the `processing` event
// SessionDetail = SessionSummary + full session.json fields + files: ["mic.wav", ...]
//   + folder: absolute path of the session folder (the UI opens the folder locally — engine is local)
//   files / folder: null for a backend without folders (30): STORAGE_BACKEND=sqlite since phase 32
//   (the audio is in the database)
//   + storage: "sqlite" | "files" (31)
//   + audio: {"mic": 83.4, "system": 83.4, "mixed": 83.4} (32): every playable track and its

{"segment_id": "system-000013", "channel": "system", "speaker_id": "system:2", "label": "User 2",
 "start": 83.12, "end": 87.9, "text": "...", "edited": false,

```

## WebSocket `/ws`

One connection per UI. Server → client messages only (commands go through HTTP). Envelope:

```json
{"type": "segment", "session_id": "20261015_202358", "data": { }}
```

| Type | Phase | `data` | When |
|------|-------|--------|------|
| `status` | 06 | `{status, duration_seconds}` | on every status change and every 1 s while recording |
| `level` | 06 | `{channel, rms_db}` | ~10 Hz per channel while recording (UI meters, 08) |
| `segment` | 06 | `Segment` | each committed transcript segment |
| `language_detected` | 06 | `{language}` | once, when `auto` locks the language |
| `minutes_ready` | 06 | `{session_id}` | minutes written |
| `voice_command` | 50, 59 | `{action, phrase, question, answer_id, request_id, at}` | a voice command was heard in the microphone while recording (after the echo dedupe); `minutes` then gives `partial_minutes_ready` with `origin` `voice` covering the meeting up to `at`, the second the wake word was said (59), `ask` gives `answer_chunk` / `answer_done` with this `answer_id` (`voice-…`) and `origin: "voice"`; `request_id` is its entry of the request history (59) |
