# Phase 17 — Crash recovery

## Goal

Never lose a meeting: if the engine or the machine dies mid-session, detect the interrupted session
on the next start, repair its files and finalize it (mix, diarization, minutes).

## Scope

**Engine**

| File | Content |
|------|---------|
| `session.py` | heartbeat every `AUTOSAVE_SECONDS`: `session.json` gets `last_heartbeat_at` and `duration_seconds` |
| `output/sinks.py` | `JsonlSink` flushes + `os.fsync` per segment |
| `storage/recovery.py` | `find_interrupted(store)` (status `recording`/`paused`/`finalizing` and no live session in this process) → mark `interrupted`; `repair_wav(path)` rewrites RIFF/data sizes from the file size; `recover(session_id)` → repair both WAVs, pad to equal length, run the remaining stop steps (mix, diarize if enabled, minutes) → `done` |
| `__main__.py` | `recover [<session_dir> | --all]` |
| API | `POST /sessions/{id}/recover`; `recovery_available` event sent on WebSocket connect |
| `config.py`, `.env.example` | `AUTOSAVE_SECONDS` |

**UI**: on `recovery_available`, a dialog lists the sessions (date, duration) with "Recover" and
"Later"; progress via `status` events.

## Design notes

- Transcript lines already flushed are kept; the last unfinished window is lost (≤ `CHUNK_SECONDS` +
  carry) — acceptable and documented.
- Recovery never deletes data; if repair fails the session stays `interrupted` with an error message
  in `session.json`.

### Decisions and notes

- `recover()` reuses the session's own stop steps: `stop()` now ends with `_finish()` (mix,
  release transcriber, diarize, minutes, search index, `done`), and `RecordingSession.recover()`
  runs the same `_finish()` on a repaired folder, so any step added there (e.g. phase 23 action
  items after minutes) also runs on recovery.
- WAV header code lives in `storage/wav_repair.py` (keeps `recovery.py` under ~200 lines). A
  missing or 0-byte WAV (crash before any audio) becomes a valid empty WAV; an unreadable header
  raises `WavRepairError` and the session stays `interrupted` with `recovery_error`.
- A half-written last `transcript.jsonl` line is moved to `transcript.jsonl.damaged` (never
  deleted), so every reader can load the transcript.
- `find_interrupted(store, live_ids, stale_after=0)`: `serve` uses only the process criterion
  (sessions not live in this process), so a session killed seconds ago is offered at once. The CLI
  passes `stale_after = 2 * AUTOSAVE_SECONDS + 5` so it never touches a session another process
  (e.g. a running `serve`) is still recording; without a heartbeat it falls back to `started_at`.
- API: `SessionManager.recover(id)` uses the single active-session slot (VRAM rule): while a
  recovery runs, `POST /sessions` and another recover get `409 session_already_active`; recovering
  during a recording is refused the same way. Not interrupted: `409 session_not_interrupted`.
  A failed repair publishes `error` `recovery_failed` (localized). Progress: `status` events
  (`finalizing` → `done`) carrying the recovered session's id. `recovery_available` is sent once
  per WebSocket connect, right after the first `status` message, only when the list is not empty.
- UI: the "dialog" is an in-window card docked under the notifications of `MainWindow` (bound to
  `MainViewModel.Recovery`), not a separate window: no code-behind, and only an insertion in
  `MainWindow.axaml` (phases 19/20/29 also edit it). "Recover" queues every listed session and
  recovers them one at a time (the engine allows one), moving on at `status done` /
  `interrupted` or `error recovery_failed`; recovery `status` events also drive the main state
  (`finalizing` disables Start, `done` reloads History). "Later" closes it; the engine offers
  the sessions again on the next connect.

### Manual check recipe

Status: **pending manual check**. Run on the reference machine, one phase at a time (audio is
shared). Commands from the repo root; the engine `.env` is the usual one (Ollama running with
`OLLAMA_MODEL` pulled).

**A. Without the microphone (simulated crash).** Already dry-run in the phase session with
`GENERATE_MINUTES=false` (folder repaired, `mixed.wav` written, `transcript.jsonl.damaged` made,
`done`, second run "not interrupted"); repeat it with minutes on.

1. Save as `make_crashed_session.py` (anywhere outside the repo) and run
   `.venv/Scripts/python make_crashed_session.py engine/recordings engine/tests/data/speech_en.wav`
   (use your `OUTPUT_DIR` if it is not `engine/recordings`; run the engine from `engine/`):

   ```python
   import json, shutil, sys, wave
   from datetime import datetime, timedelta
   from pathlib import Path

   out, speech = Path(sys.argv[1]), Path(sys.argv[2])
   started = datetime.now().astimezone() - timedelta(hours=1)
   folder = out / started.strftime("%Y%m%d_%H%M%S")
   folder.mkdir(parents=True)
   shutil.copy(speech, folder / "mic.wav")
   with wave.open(str(folder / "system.wav"), "wb") as wav:  # shorter, silent system track
       wav.setnchannels(1); wav.setsampwidth(2); wav.setframerate(16000)
       wav.writeframes(bytes(16000 * 2 * 2))
   for name, cut in (("mic.wav", 1001), ("system.wav", 0)):  # stale header, lost tail
       path = folder / name
       with path.open("r+b") as file:
           file.seek(path.read_bytes().index(b"data") + 4)
           file.write(b"\0\0\0\0")
           if cut:
               file.truncate(path.stat().st_size - cut)
   segments = [
       {"segment_id": "mic-000001", "channel": "mic", "speaker_id": "mic", "start": 0.3,
        "end": 2.5, "text": "We will ship the beta on Friday.", "words": []},
       {"segment_id": "mic-000002", "channel": "mic", "speaker_id": "mic", "start": 3.0,
        "end": 5.4, "text": "Ana owns the release notes.", "words": []},
   ]
   lines = "".join(json.dumps(s) + "\n" for s in segments) + '{"segment_id": "mic-0000'
   (folder / "transcript.jsonl").write_text(lines, encoding="utf-8", newline="\n")
   stamp = started.isoformat(timespec="seconds")
   meta = {"schema_version": 1, "id": folder.name, "status": "recording", "started_at": stamp,
           "ended_at": None, "duration_seconds": 4.0, "last_heartbeat_at": stamp,
           "language": "en", "language_source": "selected", "app_language": "en",
           "template": "general", "vocabulary": [], "devices": {}, "pauses": [],
           "settings": {"CHUNK_MODE": "vad", "CHUNK_SECONDS": 5,
                        "WHISPER_MODEL": "large-v3-turbo", "MIX_MODE": "mono"}}
   (folder / "session.json").write_text(json.dumps(meta, indent=2) + "\n", encoding="utf-8")
   print(folder)
   ```

2. CLI: `cd engine` then `../.venv/Scripts/python -m vozata recover recordings/<printed id>`.
   Expect "Recovering the interrupted session …", then "Recovered: …", exit code 0. The folder
   now has `mixed.wav` and `minutes.md` (beta on Friday / Ana), `transcript.jsonl` has 2 lines,
   `transcript.jsonl.damaged` holds the half line, `session.json` is `done` with
   `duration_seconds` ≈ 5.7 and `ended_at`; `mic.wav` / `system.wav` / `mixed.wav` open in a player
   with the same length. Running the command again prints "… was not interrupted …" (exit 1).
3. UI: make a second folder with the script, then start the app
   (`dotnet run --project ui/src/VozAta.Desktop`). Expect the card "Recover interrupted
   recordings" under the notifications, listing the session's date and `00:00:04`. Click
   **Recover**: the status shows *finalizing*, Start is disabled, then *idle*; a notification "The
   session of … was recovered." appears; History shows the session with minutes. Make a third
   folder, restart the app and click **Later**: the card closes, nothing changes on disk
   (`session.json` says `interrupted`); it reappears on the next start.
4. API (optional): with `serve` running, `curl -X POST http://127.0.0.1:8765/sessions/<id>/recover`
   → `202`; again → `409 session_not_interrupted`; an unknown id → `404`.
5. Failure path: make a folder, overwrite its `mic.wav` with a few bytes of text, recover from the
   UI: an error notification "Session … could not be recovered (mic.wav has no RIFF/WAVE header)…",
   the session stays `interrupted` with `recovery_error` in `session.json`, files untouched.

**B. Real crash (acceptance criterion, needs the microphone).** Start the app, record ~1 min
while speaking (let a few transcript lines appear), then in Task Manager → Details end the
engine's `python.exe` (pick the process by its PID / command line `-m vozata serve`; never kill
by image name). Close and reopen the UI: the recovery card lists the session with about the
recorded length. **Recover** → it ends `done`; the session folder has playable `mic.wav`,
`system.wav`, `mixed.wav` (same length), the transcript lines that were on screen (except at most
the last unfinished window), and `minutes.md`. With `DIARIZATION_ENABLED=true` (needs `HF_TOKEN`)
`transcript.diarized.jsonl` is also written; search finds the session's words.
